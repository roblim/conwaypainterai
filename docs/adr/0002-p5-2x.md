# 2. Upgrade to p5 2.x and keep it

- **Status:** Accepted
- **Date:** 2026-10-15

## Context

The app ran on p5 0.5.14 (2017) plus the separate p5.dom add-on. Three options were considered:
the smallest upgrade that works (1.x), current p5 (2.x), or replacing p5 with a hand-written
Canvas/WebGL renderer.

## Decision

Upgrade to p5 2.x and keep p5 as the rendering and input layer for the long term. Performance
work in Phase 3 happens within p5 (for example offscreen buffers, fewer per-cell shape calls,
or p5's WebGL mode) rather than by removing it.

## Consequences

Code changes that p5 2.x required:

- **Touch:** `touchStarted`/`touchMoved`/`touchEnded` are gone. Touch now arrives as pointer
  events through `mousePressed`/`mouseDragged`, which already paint. CSS `touch-action: none`
  on the canvas replaces the old `return false` scroll blocking.
- **Keys:** key constants such as `BACKSPACE` and `ENTER` are now `KeyboardEvent.key` strings,
  so key handling switches on `key` rather than `keyCode`.
- **Async draw loop:** `draw` runs from an `async` `_draw`. This mattered for the benchmark,
  which has to wait for the frame's promise to settle.
- **Friendly Error System:** disabled outside dev, as p5 recommends for production. It costs
  time every frame, and its sketch verifier re-fetches page scripts to lint them.
- p5.dom is part of core, so the add-on is gone.

p5 2.x ships its own TypeScript types (`types/p5.d.ts`), which matters for Phase 2.
